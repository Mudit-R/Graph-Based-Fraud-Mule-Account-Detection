MODULAR ARCHITECTURE

The complete platform for Graph ML fraud defense

Designed from the ground up for high-throughput payment rails. Combining relational graph topology, gradient boosted decision trees, and sub-millisecond feature caching.

Multi-Head Graph Attention (GAT)

Unlike standard GCN isotropic averaging, GAT dynamically weighs transaction edges with multi-head attention. It identifies illicit hub routing even when bad actors deliberately disguise behavior with innocent decoy transactions.

Dual-Layer Nearline Serving

Live multi-hop GNN message passing is too slow for real-time payment SLAs (>50ms). Radar 3D computes graph embeddings nightly and caches them in a Redis 7 feature store, serving risk scores in under 0.85ms at checkout.

Imbalance-Aware Focal Loss

In extreme 0.25% fraud class imbalance, standard cross-entropy fails. Our Focal Loss objective ($\alpha=0.5, \gamma=2.0$) downweights easy negative gradients by up to 10,000x, forcing the network to focus on evasive mule signatures.

22-Dimensional Feature Engine

Combines PageRank centrality, K-core graph decomposition, in/out degree ratios, balance drain speed, night transaction ratios, and 24h/7d velocity surges into a unified feature tensor.

1. Why GAT Attention Beats Isotropic GCN

Standard GCN averages all incoming neighbors equally. In sparse payment graphs, an account connected to 50 normal users and 1 fraud hub suffers from over-smoothing. GAT learns dynamic edge attention weights $\alpha_{ij}$:

$$\alpha_{ij} = \frac{\exp(\text{LeakyReLU}(\mathbf{a}^T [W\mathbf{h}_i \,||\, W\mathbf{h}_j]))}{\sum_{k \in \mathcal{N}(i)} \exp(\text{LeakyReLU}(\mathbf{a}^T [W\mathbf{h}_i \,||\, W\mathbf{h}_k]))}$$

2. Mathematical Imbalance: Focal Loss

With $0.25\%$ fraud accounts, standard cross-entropy is swamped by easy negative gradients. Focal Loss downweights easy examples by up to 10,000x:

$$\text{FL}(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t) \quad (\alpha=0.5, \gamma=2.0)$$

3. Dual-Layer Serving Architecture

Live GNN message passing takes >50ms over 3.28M nodes, violating payment gateway SLAs. Our architecture decouples nightly PyG batch inference into a Redis Feature Store, serving sub-millisecond nearline scores.

$$\mathbf{Score}_{\text{prod}} = 0.5 \cdot \text{XGBoost}(\mathbf{x}_{\text{tabular}}) + 0.5 \cdot \text{Redis}_{\text{GAT}}(v)$$
